# 公开阅读页 WebKit 验证

2026-10-09 使用 Playwright 1.64.0 和 Windows WebKit 27.2，对实际 HTTPS 生产入口进行匿名只读验证。测试采用 iPhone 13 设备配置，移动视口为 390×844，另外检查 678 和 1100 像素宽度。没有关闭 TLS 证书校验，没有登录、写入学习数据或调用配音供应商。

## 已验证行为

范围是 Hargow 的 `starter-teahouse-arrive` 和 Brioche 的 `a1-bakery-buy-breakfast`，不是所有课程或所有页面。

- 点击词条打开知识卡并播放真实录音；点击头像显示译文并播放整句。
- 全篇播放、暂停、续播正常；选择 1.25 倍速后，实际播放中的媒体元素 `playbackRate` 为 1.25。
- 卡片打开具有 `knowledge-enter` 动画，打开前后页面宽度保持；三个宽度无横向溢出。移动端使用弹层，宽屏使用侧栏。
- 长按播放器打开自定义倍速菜单，菜单在移动视口内。此次长按是鼠标指针按住 650ms，不能作为真实触屏长按验收。
- 通过个人头像进行 SPA 导航后，播放停止，访客本次会话内的倍速偏好保留。访客完整刷新后的持久化不在此结论内。
- Hargow 单正文课程没有多余的正文切换标签；Brioche 短文模式没有对话头像或对话行，播放和暂停正常。
- 最终完整运行及短文专项均以退出码 0 完成，没有捕获到页面异常或媒体错误；最终完整运行的初始导航 SSL 重试次数为 0。

播放器验证保留原生 `Audio` 和原生 `play()`，只记录返回结果及媒体状态。短词音使用真实 `play()` 成功回执，整篇播放另外观察非暂停状态和时间推进，避免把模拟事件当作播放证据。

## 测试修正与证据边界

早期运行遇到一次初始导航 `SSL connect error`，另有访客硬刷新后偏好断言失败。导航只为该明确错误加入一次有界重试，证书校验保持；偏好测试改为产品真实的 SPA 导航路径。没有据此修改生产代码或宣称网络原因已经确定。

加严媒体验证时，极短词音未留下 `playing` 事件记录，但媒体时间已推进、没有媒体错误。测试改为记录原生播放承诺成功，保留媒体错误检查，并重新完整运行两个产品。失败运行不计入最终通过结果。

本机私有证据目录为 Hargow 的 `.local/private/webkit-20261009/`，包含最终 `result.json`、两产品移动端截图及媒体诊断。临时测试程序和独立浏览器运行时在 Chef 的 `.local/qa/`，不进入产品仓库或公开源码。此轮未变更生产镜像、数据库或产品框架引用。

Windows WebKit 与设备模拟不等于真实 iPhone Safari。真实触屏长按、iOS 音频限制、锁屏/后台切换、屏幕阅读器和真人音质审听仍需独立验收。
